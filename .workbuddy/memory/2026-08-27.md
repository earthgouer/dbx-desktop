### 突破过程（接 8/26 未完成）
- 仓库 earthgouer/dbx-desktop 是**公开仓库** → 改用 api.github.com 直接查 run/jobs/artifacts，
  不再依赖被网络限制的 raw.githubusercontent.com。
- 逐步定位 Build AppImage 0 秒失败的真实原因（三个隐藏坑）：
  1. **缺 `custom-protocol` feature**：tauri v1 生产构建（静态目录 devPath/distDir）必需，
     Cargo.toml 加 `[features] custom-protocol = ["tauri/custom-protocol"]` → 编译通过。
  2. **缺 `wget`**：ubuntu:20.04 容器镜像无 wget，tauri v1 的 appimage.sh 第一步
     `wget -q -N` 就 command not found + `set -e` 静默失败 → 补装
     `wget file libfuse2 desktop-file-utils` → AppImage 打包成功。
  3. 诊断技巧：build 步骤改为逐行 `>> /tmp/ci.log` 顺序追加（无复合命令/管道），
     失败后用 `bash -x` 重跑生成的 `build_appimage.sh` 暴露失败行；
     ci_report.py 推送完整日志（200k 上限）到 ci-logs 分支。
- **最终产物**：`dbx-desktop_0.1.0_amd64.AppImage`（71.2 MB，sha256 825e2ce6...），
  在 ubuntu:20.04（glibc 2.31 + WebKitGTK 4.0）容器内构建 → 与麒麟 V10 兼容。
  artifact 名 `dbx-desktop-appimage`（70.5MB，保留至 9/26）。
- 环境变量经验：`CARGO_BUILD_JOBS=2` + `CARGO_INCREMENTAL=0` 下编译 3m15s 稳定通过
  （早期一次在 Compiling icu_provider 后进程被静默杀死，降并行度后未再出现）。
- 最终清理：删除 probe 步骤/ci_report.py/ci-logs 上报/bash -x 追踪；
  保留 apt old-releases 兜底 + wget 依赖 + 失败日志 artifact。
