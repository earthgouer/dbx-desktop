## dbx-desktop: GitHub Actions AppImage 构建（麒麟 V10 / glibc 2.31）

- 目标：用 GitHub Action 打出兼容中国麒麟 V10（glibc 2.31 + WebKitGTK 4.0）的 AppImage。
  Tauri 已降级到 v1（v2 强依赖 WebKitGTK 4.1/glibc≥2.35，与麒麟不兼容）。
  构建基础用 `ubuntu-22.04` runner + `container: ubuntu:20.04`（GitHub 已退役 20.04 托管 runner）。
- 本地验证：`cargo check`（macOS，1.98.0）对 Tauri v1 编译通过，仅 3 个无害 warning；
  图标齐全、package-lock/Cargo.lock 一致（tauri 1.8.3 / window-state 0.1.1 / api 1.6.0 / cli 1.6.3）。
  结论：代码层面无问题，CI 失败在构建环境。
- 关键修复（commit 8227834）：
  1. apt 加 old-releases.ubuntu.com 兜底——Ubuntu 20.04(focal) 2025 已退出标准支持，
     标准源可能失效，这正是反复卡在依赖安装/构建的根因嫌疑。
  2. 诊断双通道：`.github/scripts/ci_report.py` 在成功写 `ci-logs/success.log`、
     失败写 `ci-logs/build.log`（公开分支，可经 raw.githubusercontent.com 无 token 读取）；
     同时 `build.log` 始终上传为 artifact，失败时打印尾部 150 行。
  3. 保留 `push:` 临时触发器（跑通后需移除），清理 lib.rs dead_code 警告，删 surface_error.py。
- 环境限制：本机无 `gh` CLI / GITHUB_TOKEN，无 Docker，arm64 无法直接编 linux/amd64；
  因此无法直接读 CI 日志或触发 run，改用公开 ci-logs 分支轮询结果。
- 待办：等 CI 跑完看 ci-logs 结果；成功后移除 `push:` 触发器恢复仅 workflow_dispatch。
