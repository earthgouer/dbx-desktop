## dbx-desktop: Tauri v1 AppImage CI 调试

- GitHub Action `Build AppImage` 在 `ubuntu:20.04` 容器内卡死于第 7 步 `apt-get install libwebkit2gtk-4.0-dev`。
  诊断依据：GitHub API(只读) 查到 run 状态，前 6 步均 completed（含 `apt-get update` + 装 git/curl），证明网络与 apt 正常，卡点就是依赖安装步骤。job logs 需 admin 权限(403) 拉不到。
- 根因高概率：(1) 容器内缺少 `DEBIAN_FRONTEND=noninteractive` 导致 debconf 交互卡 stdin；或 (2) WebKitGTK 依赖巨大 + 免费 runner 拉 `archive.ubuntu.com` 慢/卡连接，且 step 无 timeout 一直挂到 6h 上限。
- 修复(commit 3c22a98)：两个 workflow 的 Linux 依赖步骤统一加固 —— 显式 `DEBIAN_FRONTEND=noninteractive`、apt 加 `Acquire::Retries=5` 与 `http/https Timeout=60`、安装步骤加 `timeout-minutes: 30`，并补齐 Tauri v1 实际需要的 `libssl-dev`/`libxdo-dev`/`libgtk-3-dev`。
- 背景：目标机 中国麒麟 V10 = glibc 2.31 + WebKitGTK 4.0，故用 `ubuntu-22.04` runner + `container: ubuntu:20.04` 编译（GitHub 已停用 ubuntu-20.04 hosted runner）。Tauri 已从 v2 降级到 v1 以兼容 WebKitGTK 4.0。
- 注意：当前卡死的 run 需用户在 GitHub UI 手动 Cancel，再重新 Run（workflow_dispatch）。只读 token 无法取消/触发。
- 兜底方案（若加固后仍卡）：预构建一个已装好工具链的 Docker 镜像推到 GHCR，避免每次跑都 apt 下载数百 MB。

## dbx-desktop: 第二轮 CI 报错 (npm ci 失败)

- 加固后重跑 run 32953335930 仍 failure，但第 7 步 apt 已成功，新卡点在第 8 步 `npm ci`（Install frontend dependencies）。
- 根因：只改了 `package.json` 把 `@tauri-apps/api`/`cli` 降到 `^1`，但 `package-lock.json` 仍是 `^2`，`npm ci` 强制要求两者同步 → 直接报错。
- 修复(commit f3d7d1b)：本地 `npm install` 重新生成锁文件，解析为 api 1.6.0 / cli 1.6.3（v1）并提交。教训：改 `package.json` 后必须同步锁文件，否则 `npm ci` 必挂。
